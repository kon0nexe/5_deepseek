# ХК «Динамо-Минск» — единый комплект Oracle 19c + Node.js

В комплект входят: автоматическая установка Oracle Database 19c в Docker, исходные SQL/PLSQL-скрипты курсового проекта, расширение для веб-приложения, демонстрационные данные, 100 000 тестовых строк, импорт/экспорт JSON, примеры RMAN и Node.js сайт.

## Самый короткий путь

1. Установи Docker Desktop (Linux containers / WSL2), Node.js 22 LTS и SQL Developer.
2. Войди в Oracle Container Registry: `docker login container-registry.oracle.com`; прими условия репозитория Database Enterprise в Oracle Container Registry.
3. Для чистой установки запусти `01_INSTALL_ALL.bat`, выбери `[1]` (новый контейнер) или `[2]` (пустая PDB существующего контейнера).
4. Для уже созданной схемы `HK_DINAMO`, чтобы ничего не пересоздавать, выбери `[3]`. Это рекомендуемый режим для существующей учебной базы: он добавит только `PKG_WEB_API`, исправит Unicode-строки демо-матча, безопасно дополнит места до 10 000 и создаст/обновит `HK_WEB_APP`.
5. После успешной установки запусти `02_START_WEB_APP.bat`.
6. Перейди на `http://localhost:3000/health`, затем на `/setup` и создай MAIN_ADMIN.

## Режимы установщика

- **1 — чистая установка в новом Oracle 19c контейнере.** Контейнер и данные создаются в отдельной папке. Существующие контейнеры не удаляются. Для загрузки образа требуется доступ Oracle Container Registry.
- **2 — полная установка в уже запущенный контейнер.** PDB должна быть пустой: если `HK_DINAMO` уже существует, установщик остановится без удаления данных.
- **3 — добавить приложение к существующей HK_DINAMO.** Сохраняет существующие таблицы, пользователей схемы, 100k тестовых билетов и другие данные. Нужно ввести пароль владельца `HK_DINAMO`; ввод скрыт.

## Что будет создано

Схема `HK_DINAMO`, Oracle роли/пользователи `HK_USER`, `HK_ADMIN`, `HK_MAIN_ADMIN`, измерения `DIM_TIME`, `DIM_STADIUM`, `DIM_SECTOR`, `DIM_PLAYER`, `DIM_FAN`, `DIM_MERCH`, `DIM_MATCH`, факты `TICKETS`, `MERCH_ORDERS`, `FACT_MATCH_STATS`, `FAN_PLAYER_FAVORITES`, `APP_USERS`, представления, триггеры, функции и пакеты PL/SQL. В конце создаётся `HK_DINAMO.PKG_WEB_API` и отдельный минимально привилегированный `HK_WEB_APP` с `CREATE SESSION` и `EXECUTE` на пакет шлюза (без прямых прав DML на прикладные таблицы).

В чистом режиме начальный скрипт загружает справочные данные и минимум 100 000 тестовых билетов. Расширение добавляет до 10 000 мест для демонстрационного матча. В результате таблица `TICKETS` содержит не менее 110 000 строк.

## Unicode / русские символы

- SQL-файлы комплекта сохранены в UTF-8 без BOM.
- SQL*Plus внутри Linux-контейнера запускается с `NLS_LANG=AMERICAN_AMERICA.AL32UTF8` и `LANG=C.UTF-8`.
- Демонстрационные кириллические значения в seed SQL используют `UNISTR('\XXXX')`, поэтому их вставка не зависит от кодовой страницы консоли.
- `ASCIISTR` из текущей базы уже показывал правильные Unicode code point-ы для «Минск-Арена» и названия матча. Это означает, что данные были записаны корректно; вид `����` в SQL Developer — отдельная проблема отображения/кодировки клиентского интерфейса, а не причина удалять или пересоздавать таблицы.

В SQL Developer открой `Tools → Preferences → Environment → Encoding` и выбери `UTF-8`; затем в `Tools → Preferences → Code Editor → Fonts` выбери шрифт с кириллицей (например, Consolas или Segoe UI) и перезапусти SQL Developer. Для таблицы результатов и редактора проверь, что выбранный шрифт содержит кириллицу. Выполни `HK_DINAMO_Node_App/db/06_unicode_diagnostic.sql`. Ожидаемый `NLS_CHARACTERSET` — `AL32UTF8`.

Важно: SQL Developer использует Oracle JDBC, который работает в Unicode и не использует переменную `NLS_LANG` как SQL*Plus/OCI-клиент. `NLS_LANG=AMERICAN_AMERICA.AL32UTF8` и `LANG=C.UTF-8` задаются установщиком только для SQL*Plus внутри Linux-контейнера. Если `ASCIISTR(название)` показывает коды вида `\041C\0438...`, символы сохранены правильно; исправлять нужно отображение/кодировку клиента, а не пересоздавать базу. Не выполняй `ALTER DATABASE CHARACTER SET` на существующей базе без отдельного плана миграции и резервной копии.

## Настройка Node.js

Установщик создаёт `HK_DINAMO_Node_App/.env` после успешной установки SQL, генерирует пароль `HK_WEB_APP`, `SETUP_TOKEN` и `SESSION_SECRET`, записывает секреты в `Результаты_установки\доступы_приложения_*.txt`. Храни этот файл приватно, не публикуй и не загружай его в чат. Если Node.js 22+ уже установлен, установщик также запускает `npm install` и `npm run check`; в противном случае установи Node.js 22 LTS, а затем запускай `02_START_WEB_APP.bat`.

## Веб-интерфейс на HTML/CSS/JavaScript

Клиентская часть не использует EJS и серверные шаблоны. В каталоге `HK_DINAMO_Node_App/public/` находятся три frontend-файла: `index.html` (HTML-оболочка), `styles.css` (оформление) и `app.js` (браузерный JavaScript, который запрашивает данные через REST API и строит содержимое страниц). Node.js/Express обслуживает статические файлы и API-маршруты `/api/...`. В проекте нет файлов `.ejs`, каталога `views/` и зависимости `ejs`.

## Страницы сайта

`/` главная; `/matches` календарь; `/matches/:id/seats` выбор места; `/players` состав/избранное; `/merch` каталог; `/account/tickets` мои билеты; `/admin` управление игроками, матчами, билетами, атрибутикой, JSON и OLAP; `/super/users` роли и прикладные аккаунты для MAIN_ADMIN; `/guide` описание интерфейса; `/health` проверка соединения Oracle.

Пользовательская покупка — учебная транзакция: статус билета становится `SOLD`, но платёжный шлюз не подключён. Приложение рассчитано на локальную демонстрацию, не на публичный production без HTTPS, устойчивого хранилища сессий, мониторинга и аудита.

## Важные файлы

- `01_INSTALL_ALL.bat` — запуск единого установщика.
- `01_INSTALL_ALL.ps1` — сценарий установки БД и подключения приложения.
- `HK_DINAMO_Oracle19c/` — основные SQL/PLSQL, JSON, тесты 100k, RMAN.
- `HK_DINAMO_Node_App/` — Node.js проект, шлюз PL/SQL, интерфейс.
- `Документы/` — исходный лист задания и пояснительная записка.
- `Результаты_установки/` — журналы/доступы создаются автоматически при запуске.

**Никогда не удаляй Docker volume или папку OracleData для повторной установки.** Для уже установленной схемы используй режим 3.
