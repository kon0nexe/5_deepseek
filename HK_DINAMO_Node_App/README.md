# Веб-приложение ХК «Динамо-Минск» — Node.js + Oracle Database 19c

Учебное веб-приложение для демонстрации курсовой работы «Реализация базы данных хоккейного клуба „Динамо-Минск“ с применением OLAP-технологии».

Приложение использует реальные таблицы и PL/SQL-пакеты Oracle из предоставленного проекта. Оно не содержит локальную имитацию данных и не заменяет Oracle.

## Возможности по ролям

### USER — пользователь
- регистрация и вход по логину и паролю приложения;
- просмотр состава игроков, календаря матчей и каталога клубной атрибутики;
- открытие карточки матча, выбор сектора, ряда и конкретного места на арене;
- резервирование места на 15 минут, отмена резерва или демонстрационное подтверждение покупки;
- добавление игрока в избранное и удаление из избранного;
- просмотр своих билетов.

### ADMIN — администратор
- добавление, изменение и удаление игроков;
- добавление, изменение и удаление матчей;
- добавление билетов, изменение места и цены свободного билета, продажа, возврат и удаление свободных билетов;
- освобождение истёкших резервов;
- добавление, изменение и удаление товаров атрибутики;
- импорт игроков из JSON и экспорт игроков в JSON;
- OLAP-отчёты по продажам, выручке, секторам и игрокам.

### MAIN_ADMIN — главный администратор
- получает все страницы и возможности ADMIN;
- просматривает прикладные учётные записи;
- назначает роли USER, ADMIN, MAIN_ADMIN и включает/отключает учётные записи.

Самостоятельная регистрация всегда создаёт USER. Нельзя зарегистрироваться с ролью ADMIN или MAIN_ADMIN через публичную форму.

## Архитектура безопасности

Браузер → Node.js / Express → `HK_DINAMO.PKG_WEB_API` → существующие пакеты и таблицы Oracle.

- `APP_USERS` содержит прикладные учётные записи сайта и хеши паролей (bcrypt). Это не Oracle-логины.
- `SYS`, `SYSTEM`, `HK_DINAMO` и `HK_WEB_APP` не являются пользовательскими логинами сайта.
- `HK_WEB_APP` — отдельная техническая Oracle-учётная запись приложения. Ей предоставляется только `CREATE SESSION` и `EXECUTE` на `HK_DINAMO.PKG_WEB_API`; прямые SELECT/INSERT/UPDATE/DELETE на таблицы не выдаются.
- `PKG_WEB_API` работает с правами владельца (AUTHID DEFINER) и вызывает существующие пакеты `PKG_USER_API`, `PKG_ADMIN_API`, `PKG_SECURITY_API`, а также нужные таблицы. Это единая граница доступа для веб-пула соединений.
- В старом демонстрационном `PKG_USER_API` проверяется `DB_USERNAME = SESSION_USER`; такая проверка рассчитана на прямое подключение отдельного Oracle-пользователя. Веб-приложение использует общий пул подключений под `HK_WEB_APP`, поэтому для действий сайта применяется отдельный шлюз `PKG_WEB_API`, который получает ID пользователя из проверенной серверной сессии и находит его `FAN_ID`.

**Главный администратор должен быть и в приложении, и в базе данных как прикладная запись `APP_USERS`.** Веб-страница `/setup` создаёт первого `MAIN_ADMIN` только если такой роли ещё нет и если введён `SETUP_TOKEN` из `.env`. Отдельная учётная запись Oracle DBA остаётся в SQL Developer и администрирует саму СУБД, но не используется для входа в сайт.

## Технологии

- Node.js 22 или новее, Express 5, HTML/CSS/JavaScript;
- Oracle Database 19c;
- `node-oracledb` в Thin mode — Oracle Instant Client отдельно не требуется; Thin mode поддерживает Oracle Database 12.1 и новее;
- `bcryptjs` для хеширования паролей;
- PL/SQL, `SYS_REFCURSOR`, SQL/JSON (`JSON_TABLE`, `JSON_OBJECT`, `JSON_ARRAYAGG`), `ROLLUP`, `CUBE`, `GROUPING_ID`.

## Что важно понимать о демонстрации

1. **Оплата не подключена.** Кнопка подтверждения покупки выполняет изменение статуса зарезервированного билета на SOLD и сохраняет продажу в Oracle. Это демонстрация транзакции базы данных, а не списание денежных средств.
2. Для демо-матча «Демонстрационный соперник» скрипт расширения создаёт 10 000 отдельных мест: два сектора по 5 000, 50 рядов по 100 мест. Исходные тестовые билеты с разными статусами сохраняются.
3. SQL-проект также содержит 100 000 тестовых билетов для отдельной проверки производительности. Матчи `TEST PERF %` не показываются в пользовательском календаре, но остаются в базе для администраторских/аналитических проверок.
4. Веб-импорт JSON передаёт содержимое файла в PL/SQL как CLOB и разбирает его `JSON_TABLE`. Это дополняет исходный файловый пакет `PKG_JSON_IO`, который читает файл через `UTL_FILE` и `HK_JSON_DIR`.
5. OLAP-страница выполняет запросы непосредственно в Oracle: `ROLLUP` показывает итоги по сезону/году/месяцу, `CUBE` строит срезы по сезону и категории сектора, отдельный запрос разделяет популярность игроков (избранное) и спортивную результативность (голы/передачи/очки).
6. Приложение подготовлено как учебный демонстрационный проект. Перед реальным публичным развёртыванием нужно подключить устойчивое хранилище сессий, HTTPS, CSRF-aware reverse proxy, аудит действий, резервное копирование и платёжного провайдера.

# Установка и запуск

## 1. Предварительные условия

- Windows 10/11 или другая ОС с Node.js 22 LTS;
- Docker Desktop запущен, если Oracle работает в Docker;
- Oracle Database 19c запущена и опубликована на хостовый порт `1521` (например, Docker mapping `0.0.0.0:1521->1521/tcp`);
- созданная ранее схема `HK_DINAMO` с исходными объектами и демонстрационными данными;
- SQL Developer для выполнения двух SQL-сценариев;
- имя сервиса PDB, например `ORCLPDB1`.

В `DB_CONNECT_STRING` нужно указывать опубликованный порт Docker. Если порт в Docker проброшен как `1522:1521`, тогда строка будет `127.0.0.1:1522/ORCLPDB1`.

Проверить имя PDB/service можно в SQL Developer от SYS:

```sql
SELECT name FROM v$services ORDER BY name;
```

## 2. Установить дополнительный PL/SQL-шлюз

Сначала проверь, что Oracle открыт и ты подключаешься именно к пользовательской PDB, а не к `CDB$ROOT`.

1. В SQL Developer открой соединение `HK_DINAMO` к той PDB, где уже установлены объекты проекта.
2. Открой файл `db/01_web_app_api.sql`.
3. Выполни его как Script (F5), а не как одиночный statement.
4. В конце проверь, что появились сообщения `No errors` / `PKG_WEB_API создан`.

Сценарий:
- создаёт `HK_DINAMO.PKG_WEB_API`;
- вызывает исходные пакеты проекта;
- генерирует недостающие места для демонстрационного матча, если матч найден;
- не удаляет и не пересоздаёт исходные таблицы/пользователей и не удаляет старые данные;
- повторный запуск заменяет пакет и пропускает уже существующие комбинации места благодаря проверке NOT EXISTS.

Если `SHOW ERRORS` показывает ошибки, сначала исправь компиляцию пакета — приложение до этого запускать не нужно.

## 3. Создать отдельного Oracle-пользователя веб-приложения

1. В SQL Developer создай соединение `SYS` с ролью `SYSDBA` к той же PDB.
2. Открой `db/02_create_web_user.sql`.
3. Замени в файле пароль `ChangeMe_WebApp_19c!` на собственный стойкий пароль.
4. Выполни сценарий клавишей F5.
5. Этот же пароль укажи в `.env` как `DB_PASSWORD`.
6. Вернись к подключению `HK_DINAMO` и выполни `db/03_verify_web_app.sql`: пакет должен быть `VALID`, ошибок компиляции быть не должно, количество мест на демонстрационном матче — 10 000.

Скрипт не удаляет пользователя `HK_WEB_APP`: при повторном запуске он обновляет его пароль и повторно выдаёт только необходимые права. Если пользователь уже создан с другим паролем, синхронизируй пароль в SQL-скрипте и `.env`.

## 4. Установить Node.js и подготовить конфигурацию

Рекомендуется Node.js 22 LTS (Windows x64 MSI):

- https://nodejs.org/en/download/

Проверь в PowerShell:

```powershell
node --version
npm --version
```

В каталоге проекта скопируй `.env.example` в `.env`:

```powershell
Copy-Item .env.example .env
```

Открой `.env` и укажи значения:

```dotenv
DB_USER=HK_WEB_APP
DB_PASSWORD=твой_пароль_HK_WEB_APP
DB_CONNECT_STRING=127.0.0.1:1521/ORCLPDB1
DB_POOL_MIN=1
DB_POOL_MAX=6
SETUP_TOKEN=длинный_случайный_секрет
SESSION_SECRET=другой_длинный_случайный_секрет
PORT=3000
NODE_ENV=development
APP_BASE_URL=http://localhost:3000
```

Для генерации двух секретов PowerShell:

```powershell
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```

Запусти команду дважды: один результат используй для `SETUP_TOKEN`, второй — для `SESSION_SECRET`. Не публикуй `.env` и не отправляй пароли в переписке.

## 5. Установить зависимости и запустить сайт

Открой PowerShell в папке `HK_DINAMO_Node_App`:

```powershell
npm install
npm run check
npm start
```

Либо после заполнения `.env` можно запустить `start.bat` двойным щелчком из Проводника: он проверит Node.js, при необходимости выполнит `npm install`, затем проверит синтаксис и запустит сервер.

После сообщения `Oracle подключён` открой:

- http://localhost:3000

Если приложение не запускается, проверь соединение Oracle:

```powershell
docker ps
Test-NetConnection 127.0.0.1 -Port 1521
```

В `docker ps` у Oracle-контейнера должен быть опубликован порт `1521`. Если порт отличается — исправь `DB_CONNECT_STRING`.

## 6. Создать главного администратора и роли

1. При первом запуске открой `http://localhost:3000/setup`.
2. Введи `SETUP_TOKEN` из `.env`, имя, email, логин и пароль (не менее 10 символов).
3. После сохранения откроется `/super/users`.
4. Зарегистрируй обычного пользователя через `/register`.
5. Главный администратор может изменить роль этого пользователя на `ADMIN` в разделе «Пользователи».
6. Выйди и проверь вход в отдельных ролях USER и ADMIN.

Если первый MAIN_ADMIN уже создан, `/setup` закрывается. Новый главный администратор назначается только из раздела управления пользователями.

## 8. Быстрая проверка, что сайт подключён к Oracle

Открой:

```text
http://localhost:3000/health
```

При успешном подключении вернётся JSON со статусом `ok`. Также можно выполнить в SQL Developer:

```sql
SELECT COUNT(*) AS players_count FROM HK_DINAMO.DIM_PLAYER;
SELECT COUNT(*) AS demo_seats
  FROM HK_DINAMO.TICKETS t
  JOIN HK_DINAMO.DIM_MATCH m ON m.MATCH_ID=t.MATCH_ID
 WHERE m.OPPONENT_NAME='Демонстрационный соперник';
SELECT OBJECT_NAME, STATUS
  FROM ALL_OBJECTS
 WHERE OWNER='HK_DINAMO' AND OBJECT_NAME='PKG_WEB_API';
```

Для демонстрационного матча ожидается 10 000 мест после успешного выполнения генератора, а для пакета — статус `VALID`.

## 9. Возможные ошибки

- **ORA-01017 / invalid username-password** — проверь `DB_USER`, `DB_PASSWORD` и пароль в `02_create_web_user.sql`.
- **ORA-12514 / listener does not currently know of service** — проверь `DB_CONNECT_STRING`, имя сервиса PDB и port mapping Docker.
- **ORA-06550 / PLS-00302 / package does not exist** — пакет `PKG_WEB_API` не установлен, либо сценарий выполнялся не в той схеме/PDB.
- **ORA-00942 / table or view does not exist** во время компиляции — пакет создаётся не владельцем `HK_DINAMO` или базовая схема развёрнута не полностью.
- **Нет мест в выбранном ряду** — убедись, что скрипт `01_web_app_api.sql` выполнен после загрузки исходных demo-данных и что есть матч `Демонстрационный соперник`.
- **Дата матча не добавляется** — исходный календарь `DIM_TIME` покрывает даты 01.01.2024–31.12.2035. Для дат вне этого диапазона требуется расширить календарное измерение.

## 10. Содержание проекта

- `db/01_web_app_api.sql` — расширенный PL/SQL API для веб-приложения;
- `db/02_create_web_user.sql` — отдельная учётная запись Oracle `HK_WEB_APP` и выдача EXECUTE;
- `server.js` — REST API, авторизация, роли, сессии и подключение к Oracle;
- `src/oracle.js` — пул node-oracledb, вызовы пакета, REF CURSOR и CLOB;
- `src/security.js` — middleware авторизации и CSRF;
- `public/index.html` — статическая HTML-оболочка интерфейса;
- `public/styles.css` — оформление;
- `public/app.js` — клиентская логика и формирование страниц;
- `server.js` — REST API и Node.js backend;
- `.env.example` — пример конфигурации.

Исходные SQL-скрипты базы данных остаются отдельными и не изменяются этим пакетом. Для первого развёртывания сначала установи базу по своему SQL-комплекту, затем выполни три SQL-сценария из этой папки: PL/SQL-шлюз, создание технического пользователя и проверку установки.


## В составе единого комплекта

Для полной установки БД и сайта запускайте `../01_INSTALL_ALL.bat`. Для добавления приложения к уже установленной схеме выбирайте режим 3. Этот режим не пересоздаёт базовые таблицы и сохраняет тестовые данные.


## Клиентская часть без EJS

Интерфейс полностью переведён на обычные статические HTML, CSS и JavaScript. В проекте нет каталога `views/`, файлов `.ejs` и зависимости `ejs`. Express возвращает `public/index.html`, а данные и операции передаются через JSON REST API (`/api/...`).
